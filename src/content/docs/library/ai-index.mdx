想跟上前沿，难点从来不是「信息太少」，而是**同一个消息在五个地方重复出现，真正有用的那一条被淹掉了**。

这一年我把常看的东西按用途分成了五类。判断标准很土：**过去一个月我有没有真的点开过它**。没点开过的，再有名也删。

## 三类读法，对应三种时间

- **每天两分钟**：刷一眼 HN 和 GitHub 周榜，知道「这周大家在做什么」。不求记住，只求不脱节。
- **每周半小时**：挑一份周报读完。周报的价值不在信息量，在于它替你做了取舍。
- **动手之前**：去框架和技能生态那两栏查一圈，先确认有没有现成的，再决定要不要自己写。

按这个节奏，订阅超过三份周报反而是负担——我最后只留了 Latent Space 和 The Batch 轮换着看。

## 两点说明

**版本号会过期。** 框架那栏标注的是 2026 年 11 月初的版本，这些项目基本按周迭代，看的时候以仓库页面为准。真正稳定的判断不是版本号，而是「这个框架今年的更新方向有没有变」。

**Super-agent 这一栏还很新。** DeepSeek 那篇设计探索 11 月才公开，Airtable 的 Superagent 上线四个月就下线换成了 HyperAgent，讯飞和中国电信走的是行业方案。现在下结论太早，我把它们放在一起，只是方便你一次看完这个方向目前长什么样。
