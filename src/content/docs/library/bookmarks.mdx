书签是那种「存的时候很爽，找的时候想死」的东西。

我这台机器的情况：Edge 里 716 条，最早的能翻到几年前学 C 语言的时候。它们散在十几个文件夹里，同一个页面在三个地方各存了一份，还有一批链接点开是 404。真正的问题不是数量，是**没有入口**——想找的时候只能一层层点开文件夹翻。

于是我干脆把它导出来，重新整理成下面这个页面。

## 怎么做的

三步，都可以重复跑：

**一、直接读浏览器的数据文件。** Chromium 系（Edge / Chrome / QQ 浏览器）的书签是一个 JSON 文件，路径固定在用户目录下，不需要装插件，也不需要登录同步账号。

**二、去重。** 按 URL 去掉锚点和末尾斜杠后比对，同一篇文章存了三遍只留一条。这一步砍掉 18 条。

**三、分类。** 原来有十几个文件夹：嵌入式、Code、PC、Goto、Study、翻翻翻……名字是我不同时期起的，语义重叠得厉害。合并成四大类，再看每类里到底是什么。

## 主动删掉了什么

这一步比分类重要。**这个页面是公开的**，所以下面几类在生成时就排除了，不是手动一条条删的：

- **招聘网站** 46 条 — 招聘平台、投递系统、公司校招页。这类链接暴露的是求职轨迹，不该出现在公开页面。
- **一个文件夹里的 13 条** — 存的是网络工具，和这个站的主题无关。
- **内网和本地地址** 2 条 — `192.168.*` 和 `localhost`，对别人没有意义。
- **重复** 18 条。

排除规则写在 `tools/build-bookmarks.mjs` 里，是正则。想加规则改一行就行，比如把某个域名整个屏蔽掉。

## 剩下的

637 条，按原来的文件夹归成四组，可以搜标题或域名。

## 几句实话

**这不是一个「精选」。** 637 条里肯定还有大量过期的、重复主题的、当时觉得有用后来再没打开过的。我没做人工筛选——那是几百次点击的活，而且标准会一直变。这个页面解决的是「找得到」，不是「都值得看」。

**CSDN 占了 112 条。** 早年搜 C 语言、单片机的问题，搜索结果前十有八个在 CSDN。现在这些链接里有一半打不开了，但我没删——留着能看出自己当年是怎么学的，也算一种记录。

**下次换电脑只要跑一遍脚本。** 浏览器装了哪些、配置文件在哪，脚本开头写着；`node tools/build-bookmarks.mjs` 跑完，这个页面跟着更新。
